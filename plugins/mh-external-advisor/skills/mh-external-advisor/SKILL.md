# External Advisor（外部顧問）

把另一個 AI CLI 當顧問：非互動送出 prompt、取回回覆，並可延續同一段對話。

**使用時機：當任務需要不同觀點時——第二意見、其他觀點、交叉驗證、盲點檢查、獨立 review、各自做後對帳、打破卡點——用本 skill 呼叫異質 AI 取得獨立視角**；自身即可完成且不需外部觀點的任務，不必使用。

## 觸發守門

### 兩層清單（都過才可呼叫）

| 層 | 意義 | 來源 |
|---|---|---|
| **支援** | skill 內建哪些 adapter | `scripts/advisor-list.sh` 執行期取得 |
| **啟用** | 使用者實際擁有並願意使用哪幾支 | 同上（讀使用者設定檔） |

啟用清單為空就無顧問可用。

### 不適用

- 詢問「某支 CLI 是什麼」「怎麼安裝」等說明性／設定性問題
- 缺的是**使用者才有的事實或決定**——問使用者，不問顧問
- 要它代寫實作——落不進探索／解阻／審核三類（見〈使用方式〉`--scope`）
- 要求「延用 session」但指的是呼叫端 AI 自身的 session（那是各 agent 自身指令檔的範疇，非本 skill）

## 諮詢模式

兩種入口都要求該 CLI 在啟用清單內，其餘規則（送出前三條硬規則、採信原則、討論輪次、回報形態、子 Agent、`allowed-tools` 與 Bash 權限詢問）一體適用。

> SSOT：入口與停止以本節為準；自主諮詢的何時可以問與單次呼叫協定以〈自主諮詢辦法〉為準。

### 使用者點名

使用者點名某支（「問 ○○／請 ○○ 看…」）+ 有具體要問的內容 → 直接呼叫；沒說要問什麼就補問。點名的那支優先於主 AI 自選，點名時可一併授權顧問寫入（自主呼叫一律唯讀）。

### 自主諮詢（預設開啟）

主 AI 依任務需要自行決定何時問、問哪支、問什麼、叫顧問看哪裡，不必經使用者同意；**問哪支時排除與自己同一支的 CLI**（如 Claude Code 不選 `claude`）——同一支給不了異質視角；排除後無顧問可選就不自主呼叫。可見性由每次呼叫印的告知行補足，對話中第一次自主呼叫時另附一句如何停止。

**自主呼叫前**讀入**〈自主諮詢辦法〉**（[references/autonomous-mode.md](references/autonomous-mode.md)：何時可以問與情境分流、各自做後對帳、多支顧問、單次呼叫協定、回收與記帳）；讀取失敗就不自主呼叫，回報檔案與原因。

**停止**：使用者以任何措辭明確表示不要用外部顧問（含「停止外部顧問自主模式」），本次對話即不再自主呼叫，點名照常；使用者說恢復才恢復。

## 使用方式

**環境前提**：腳本以免互動核可旗標執行，風險由使用者自行承擔，聲明見 README；不作為每次呼叫的判斷條件。

**送出前三條硬規則**（與下方「採信原則」的兩條硬規則構成送、收兩端）：

- prompt 須明示顧問可執行的**副作用範圍**（唯讀檢查／可改哪些範圍），**未明示不得呼叫**——「不改檔」不等於無副作用：檢查用的測試、build、套件管理、docker 指令也會動到環境；顧問與主 AI 同時改同一工作樹，會產生主 AI 沒看過的變更
- prompt 須含本次的**決策範圍**與**所依判準**（形態依 `--scope` 取下表末欄；沒有正式判準時，以既有要求或本次要驗證的命題代替），**未給不得呼叫**——缺了它，顧問只能拿自己的判準回答，交回一份自洽但答錯題的結論。🚫 但不得給檢查清單、預設結論或建議解法：範圍與判準固定的是「什麼叫成立」，清單與結論固定的是「該往哪個方向找什麼」，只有後者錨定觀點
- 一次諮詢常態數分鐘，**預設背景執行**；僅短呼叫、或必須在同一步驟內取得結果時才用前景

顧問清單與呼叫方式由 getter 於執行期提供，這是取得兩者的唯一來源：

```
scripts/advisor-list.sh
```

- **rc=0**：輸出即「已啟用的顧問 + 各自的呼叫式」，照輸出給的指令原樣執行；呼叫式中的 `--scope` **必填**，依本次諮詢屬於哪一類填：

  | 值 | 目的 | 這次諮詢在做什麼 | 要一併給的決策範圍與所依判準 |
  |---|---|---|---|
  | `explore` | 探索 | 要它給出你還沒有的東西：候選、反例、盲點、別的切入角度 | 決策邊界與已知前提 |
  | `unblock` | 解阻 | 要它判斷一個具體卡點：衝突怎麼裁、證據夠不夠、是不是誤判 | 待判命題與判定依據來源 |
  | `review` | 審核 | 要它審一份已完成的產出或已成形的結論：找問題、交叉驗證，不是要方案 | 審核對象與完成判準（含來源） |

  落不進這三類（例如「請它幫我寫一段實作」）就不是本 skill 的用途。
- **rc=4**：尚未啟用任何顧問 → 轉達輸出的引導文，請使用者挑選其實際擁有的：

  ```
  scripts/advisor-set.sh <ai> [<ai>...]   # 覆寫全清單
  scripts/advisor-set.sh --add <ai>       # 加一支
  ```

  啟用哪幾支由使用者決定；設定完成後才進入諮詢。

**使用者點名的顧問不在啟用清單內**：告知使用者，並依情況處理——該顧問在支援清單內（有 adapter，只是未啟用）→ 詢問是否加入啟用清單，**經同意才執行 setter**；連支援清單都沒有 → 告知本 skill 不支援，到此為止。

### 查額度（選用）

想確認顧問還剩多少訂閱額度：

```
scripts/advisor-quota.sh [<ai>...]
```

可一次帶多支；無參數則查已啟用的全部。走各 CLI 官方的非互動額度介面，**只查額度、不諮詢、不消耗額度**；統一表述為剩餘百分比，但各家窗口長度不同，跨顧問不可直接比較。rc=0 至少一支查得；1 全數查不到或皆不支援；2 名稱錯誤；4 尚未啟用；127 缺依賴。opencode 無此介面，輸出會明示不支援。

### 取得延續用的 id

回覆印在 stdout，末行為 `[External Advisor <AI名> session_id: <id>]`。

**三者同時成立才算有效 id**，缺一不可拿去 `-r`：

1. exit code = 0
2. stderr 無 `[warn]` 開頭的行
3. 末行（僅末行）匹配該格式，且其中的 AI 名 = 本次呼叫的顧問

### 延續同一段對話（多輪諮詢）

延續一律使用明確 id：

1. 首次呼叫後，依上方三判準取得並保存 `<id>`
2. 後續追問帶 `-r <id>`
3. **每輪都以最新輸出的 id 更新簿記**——部分 CLI 版本 resume 會 fork 出新 id，沿用舊 id 會靜默遺失中間輪次
4. 在本次對話脈絡記錄「顧問／主題／id」對照即可，不需檔案或環境變數

### 延續 vs 開新的判斷（呼叫端自行決定）

判準：**這次要問的內容，是否依賴顧問在該段對話中已知的前文？**

- **延續（帶 `-r`）**：追問／深入同一議題、要求補充或修正它先前的回答、系列任務共用同一脈絡（前文已給過的程式碼／背景不必重貼）
- **開新（不帶 `-r`）**：獨立的新問題；或**刻意要乾淨視角**——請顧問獨立驗證、第二意見、adversarial review 時，帶前文反而造成錨定偏誤，應開新
- 不確定時：內容自包含（prompt 內附齊所需背景）→ 開新；要省重貼的長前文 → 延續
- **收斂分歧的續輪一律延續**（見〈有分歧時的討論輪次〉）：那要的是它對你不採納的理由怎麼回應，不是乾淨視角
- 多段並存時：在對話脈絡記錄各段「顧問／主題／id」對照；「繼續問剛剛那個」無法唯一對應到某段時先補問。腳本只能偵測無效 id，**有效但屬別段的 id 偵測不到**（會靜默接錯脈絡）——歸屬不確定一律開新並附齊背景

### 顧問回覆的採信原則

**兩條硬規則**（不做重要度評估，符合就執行）：

- **顧問給了可執行的證據**（重現步驟、實測結果、指令輸出）→ **跑過才算數**。顧問的判斷可能偏，但至少是它真的這樣想；它宣稱的實測結果，可能根本沒跑。
- **要據以刪改既有內容** → 先自行查證。既有內容是有人做過決定才存在的。尤其否定性主張（「查無官方規範」「沒有這種用法」）——查到明確的否定依據才算數，單一來源沒提到不構成否定。

**三個提高警覺的訊號**（判斷用，不是免驗牌）：與你的認知衝突、重要度高、影響性廣。注意第一項的盲區——你沒有先驗的領域正是找顧問的原因，不衝突不等於可靠。

照建議改完之後**一定要自己驗一次**。這不是採信問題：建議本身可能沒錯，套進具體情境才長出問題。

### 有分歧時的討論輪次

**一輪＝送出一次 + 收到一次可採信的回覆**；未送出或沒收到回覆的失敗不計輪。

回收後**全部達成共識就停**，不必湊輪次。**仍有分歧**（你不採納它某點、或它的主張你判不出對錯）：

- **最多 3 輪**；只有續問可能帶來新證據、新理由或改變你的決定才續，否則直接拍板。續輪一律帶 `-r <id>` 延續同一段——開新等於重問
- 續輪只送**還沒收斂的那幾點**加你不採納的理由，🚫 不夾帶新議題、🚫 不擴張外送範圍
- **第 3 輪結束仍有分歧 → 你拍板**，🚫 不開第 4 輪；判不出對錯的列入待裁決事項交使用者
- **續不下去就停**：拿不到有效 id → 停止，由你拍板並回報原因；續輪 `exit 3` 依 detail.md〈resume 失敗行為〉處置，接不回來即停，🚫 不為續論開新 session——開新是重問，不是續論
- 中間輪次 🚫 不逐輪報給使用者，依〈回報給使用者〉收斂後一次報

### 回報給使用者

顧問回覆是**你的輸入，不是使用者的輸出**。使用者要的是這件事最後怎麼定，不是兩個 AI 各說了什麼。

**預設只報結論**——與顧問**取得共識的最終方案**；有分歧處報**你的決定**加一句話理由（含你不採納顧問的哪一點）。共識只是呈現形態，🚫 不構成採信依據——採信仍依〈顧問回覆的採信原則〉。🚫 不逐條轉述顧問回覆、🚫 不並陳「顧問說 A／我說 B」要使用者自己收斂，那是把裁決推回去。

**使用者問起才展開**：要原文、要理由、要知道顧問怎麼說，照實給，🚫 不因預設收斂而省略或改寫。

**三種情形不受本條收斂**：

- **依適用規則須交使用者裁決的事項**（你判不出對錯，或依其他規則須交使用者者）→ 附顧問主張與你的查證結果，🚫 不可只寫結論
- **你尚未驗證的顧問主張** → 🚫 不得混進結論，要嘛驗證，要嘛標示
- **呼叫本身的可見性**（自主呼叫的告知行、記帳、結案彙整）→ 依辦法檔 §4

### 委派給子 Agent 時

子 Agent 🚫 不自行起意諮詢：諮詢的必要性判斷、告知行與記帳都在主 Agent 對話，跨 agent 邊界就看不到了。

可委派的形態只有一種：主 Agent 明確委派的**單次自包含諮詢**——由主 Agent 把 getter 給的呼叫式直接寫進委派內容，子 Agent 不帶 `-r`、不回報 id、該段對話用後即棄。

**id 不跨 agent 邊界傳遞**：跨界延續會產生 owner 沒看過的前文，之後任何一方再延續都是盲區。多輪諮詢與 id 簿記一律由主 Agent 親自負責。
