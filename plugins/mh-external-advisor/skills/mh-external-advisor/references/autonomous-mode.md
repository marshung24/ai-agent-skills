# 自主模式執行辦法

> 本檔在使用者下達啟動指令、且來源判定通過後才讀入。SKILL.md〈授權模式〉保留啟動條件與本檔的用途、時機、排除，不重複本檔內容。
> 未啟動時本檔一律不適用，授權回到 SKILL.md 的逐次點名。

## 0. 啟動與停止

- **啟動指令**：使用者在主對話中直接說「啟動外部顧問自主模式」
- **停止指令**：「停止外部顧問自主模式」

指令的成立條件與來源信任邊界見 [SKILL.md](../SKILL.md)〈授權模式〉，本節只寫程序。

### 啟動程序

依序做完六步，**第 6 步完成前不得自主呼叫**：

1. 確認指令出自使用者本人、且是真的在下令（不是引用、討論或請你分析那句話）
2. 完整讀入本檔
3. 收集並驗證七欄（§1）：未指定者填預設，顧問未指名時依 §1 的順序取得。**環境隔離不是啟動條件**——未聲明照樣啟動，只是啟動確認要多一則警告
4. 跑 `scripts/advisor-list.sh`，確認取得的顧問在啟用清單內；不在 → 告知並停止
5. 輸出啟動確認
6. 狀態切為「已啟動」

環境隔離由使用者聲明並承擔，**主 AI 不自行判定、不代為推定，只做警告與安全聲明**——顧問可觸及範圍等同主 AI，家目錄必然有憑證，照字面技術判定永遠不成立。

### 啟動確認

啟動確認是狀態快照，🚫 不重述辦法內容：

```
自主模式已啟動
顧問：<名稱> ｜ 副作用：唯讀
作用域：<範圍>（一個工作單元） ｜ 責任層級：<執行層|決策層>
指派範圍：<正規化後的值>
允許目的：<探索|解阻|審核>
額度：每命題 1 次、每凍結點 1 次，無總配額
到期：任務完成、作用域改變、或你撤回
環境隔離：<已聲明隔離，依你的聲明採信、未經技術驗證｜未聲明——顧問權限等同主 AI，讀得到的內容都可能外送，建議在隔離環境使用>
退場：命中辦法 §9 任一條即自動停止並回報
```

七欄不完整時，輸出的是「尚未啟動 ＋ 缺哪幾欄」，不是啟動確認。

### 模式狀態

自主模式狀態**只存在本次主對話脈絡，🚫 不落檔、🚫 不寫入 `enabled.json`、🚫 不跨 session 延續**。`enabled.json` 表達的是跨 session 的「擁有並願意使用哪些顧問」，與本次對話的臨時授權是兩回事；混存會讓新 session 無聲繼承高權限。

需維持的欄位：模式狀態／七欄授權值／作用域與到期點／已問過的命題與凍結點／顧問・主題・session id／呼叫記錄摘要。

模式狀態的權威版本由**可見輸出**構成，不靠隱性記憶：啟動確認 → 每次呼叫前札記 → 每次回收後新增的呼叫記錄與餘額 → 停止或退場時的結算摘要。

### fail closed

context 壓縮或任何原因導致七欄、已問過的命題或呼叫記錄**無法完整且無歧義還原** → 視為已停止，回報使用者、須重新下達啟動指令。🚫 不得以「大致還記得」補值續用。

**辦法檔讀取失敗**：不啟動、🚫 不依記憶或摘要執行、回報檔案與原因、維持逐次授權。此情形不算 §9 退場——模式從未成立。

### 停止

停止不需讀本檔。立即清除有效授權與已用記錄，輸出停止確認（含截至停止時的諮詢摘要）。**啟動嚴、停止寬**：使用者以其他明確措辭表示要停止，即使不是固定句，一樣即時生效。

## 1. 常駐授權（七欄缺一無效）

| 欄位 | 預設 |
|---|---|
| 作用域 | 本次授權涵蓋的範圍 ＋ **責任層級**（執行層｜決策層），宣告時劃定並列進啟動確認。**一次授權＝一個工作單元**；🚫 主 AI 不得自行改判邊界（推進到下一個里程碑、換一批工項都不是新工作單元），要更多額度須由使用者分段重新宣告。🚫 不給永久全域 |
| 指定顧問 | **限一支**；宣告時指名，未指名時依下方順序取得。**🚫 主 AI 不得自行更換或在呼叫失敗時換手**——更換是使用者的權限，隨時可行使 |
| 指派範圍 | 主 AI 本次任務範圍的 repo 與檔案，含未追蹤、未提交內容；跨 repo 任務涵蓋各該 repo |
| 副作用邊界 | 唯讀。可寫入永遠逐次點名 |
| 允許目的 | 探索｜解阻｜審核 |
| 額度 | 綁事件，無總配額；見 §4 |
| 到期 | 任務完成、作用域改變、使用者撤回，任一 |

**未指名顧問時**，依序取，取到即停：

1. 本次對話中使用者**逐次點名用過**的顧問——恰好一支就取它（已經過使用者授權，同一對話延續同一意圖）；用過兩支以上 → 追問要哪一支
2. 啟用清單只有一支 → 取該支
3. 以上皆無 → **追問使用者**，🚫 不自行選

不論來源為何，取得的顧問都要列進啟動確認，讓使用者當場看得到、否決得掉。**自主模式一次只授權一支**——要第二支意見就由使用者逐次點名（使用者在場），🚫 主 AI 不得自行動用另一支。

**指派範圍不是圍欄**：顧問是完整 AI Agent，權限與讀取範圍等同主 AI，它自行讀檔，也讀得到未指派的路徑。指派範圍的作用是控制它的注意力與回覆品質，不是控制它能讀什麼。

**責任層級**決定這次授權有權做什麼決定，額度隨它而定（§4）：

| 層級 | 意義 |
|---|---|
| **執行層** | 照已定案的設計做事——實作、補測、依既有清單推進 |
| **決策層** | 產生或修改設計決策——選型、定契約、改規格 |

**諮詢目的**只有三種——**探索**（開場要異質觀點）、**解阻**（做到一半遇到狀況）、**審核**（收尾前的獨立審查）。落不進去（例如「請顧問幫我寫一段實作」）就不是自主模式允許的呼叫，退回逐次點名。各自的成立條件見 §3。

## 2. 計價身分

額度綁**命題**，不綁名稱——名稱可以換，命題不行。

- **計價鍵＝命題**：`待判定的事實 ＋ 判定依據的來源 ＋ 會被推翻的下一步`。三者相同即同一命題，🚫 不因換檔名、換模組、換工項或換措辭重取額度
- **追蹤鍵＝受影響範圍**：檔案／工項／模組 ID 的集合，只記錄不計價。同一命題橫跨 20 個工項仍算一次

一份清單有幾百個工項，就有幾百個合法名稱；沒有這條，額度形同虛設。指不出唯一命題 → 停止，問使用者。

## 3. 觸發判定

依諮詢目的分流，各用各的判準；三類都要再過共同守門。

### 探索（開場要異質觀點）

**執行層作用域下額度為 0，不得呼叫**——探索的本質是產生候選，而執行層無權產生候選；給了額度等於發一張繞過上游的許可證。

決策層下，全部成立才呼叫：

- 決策空間仍開放，替代方案會實質影響方向
- 至少兩個合理候選，或兩組會改變方向的前提
- 尚未被 SSOT、既有證據或使用者決策收斂
- 預期取得的是新候選、反例或判準，不是「再看一次」

### 解阻（做到一半遇到狀況）

依 SKILL.md〈主動建議門檻〉的四項判準，**至少兩項**成立並各自舉證（同一事實不得跨項計分）。自主模式下過門檻即可直接呼叫，不必再點名。

缺的若是**使用者才有的事實** → 問使用者，不問顧問。

**執行層作用域下限於事實查證**：觀測證據夠不夠支持受阻／有沒有既存規範或既有決策可直接裁定／找反例檢查是否誤判／證據鏈與重現條件有無缺漏。🚫 不得要求候選方案、根因分析、取捨建議或「該改哪裡」——那要回送上游。**即使方案只留在你心裡、沒寫進交付物，也是繞過層級責任。**

### 審核（收尾前的獨立審查）

時間點只有三個：**commit 前**、**發 PR 前**、**一個 milestone 完成時**（工項清單或階段性交付告一段落）。這三點的產出物才凍結得住，也還來得及改；其餘時點的「順便看一下」不是審核。

全部成立才呼叫：

- 對象已凍結成可識別版本（未提交的工作樹改動／commit／`base..head`）
- 有明確完成判準
- 結果仍來得及改
- 尚無涵蓋同一對象與同一完成判準的等價審核——**專案流程若已在同一時點要求顧問 review（如結案流程），那一次即為等價審核，🚫 不另外自主觸發**

### 共同守門（任一不成立即不呼叫）

問題與期望輸出可具體表述／所需證據在指派範圍內／沒有更便宜的本地驗證／沒有等價諮詢已覆蓋同一命題／在作用域內、且該事件的額度未用過／結果能改變下一步。

## 4. 預算

額度綁事件，**🚫 沒有工作單元總配額**：

| 類別 | 觸發事件 | 額度 |
|---|---|---|
| 探索 | 一個命題首次進入待決狀態 | 每命題 1 次；**執行層不得呼叫** |
| 解阻 | 一個具名阻塞成立（過 §3 四項判準） | 每命題 1 次 |
| 審核 | 一個凍結點成立 | 每凍結點 1 次 |

不設總配額，是因為三類的觸發條件本身就明確可判定：配額只會在大型任務（命題多、commit 多）卡關，卻擋不住真正的濫用。濫用由命題身分（§2）、觸發判定（§3）、札記閘門（§5）與資訊增益退場（§9）處理，那四道都比次數上限準。

**凍結點的身分**＝`審核對象版本 ＋ 完成判準 ＋ 交付邊界`。下列 🚫 **不產生**新凍結點：同一批改動拆成數個 commit／只修正前次審核意見／rebase、格式整理、commit 拆併／完成判準未變只增加實作進度。

**既有分組結構（Phase、批次、模組）只做歸屬與覆蓋，不生額度**：記錄這次諮詢影響哪一組、這次審核涵蓋哪些組即可。🚫 不因組數多放大額度、🚫 不因啟動新組重置額度、🚫 不得執行中改切分組來取得額度。

顧問限一支、並行 1。

🚫 不追問、不帶 `-r`、不自行動用第二支顧問（交叉驗證與多數決都不行）。呼叫失敗 → 回報使用者，不自動重送、不改問別支。

## 5. 呼叫前札記（缺任一行即放棄呼叫）

```
命題：<待判定的事實｜依據來源｜會被推翻的下一步>
影響範圍：<檔案／工項／模組 ID>
目的／觸發：<探索|解阻|審核> / 命中的判準 + 證據
我的答案：<你目前的結論>        # 寫不出 ⇒ 資訊不足，改問使用者
預期被推翻：<具體命題>          # 寫不出 ⇒ 這是儀式，不呼叫
指派範圍：<叫它看哪裡>
外送敘述：<背景要點；已做代號替換>
```

札記是寫給自己與使用者看的，**🚫 不得放進 prompt**——尤其「我的答案」與「預期被推翻」，送過去顧問就照著你的結論找，拿回來的還是你自己的視角。最後兩行只是**描述**將要送出什麼，供使用者當場否決；實際送出的內容以 §6 為準。

## 6. 呼叫方式

先跑 `scripts/advisor-list.sh` 取呼叫式，照輸出原樣執行，背景執行。prompt 只含三項：

1. **指派範圍**——叫它看哪裡
2. **副作用邊界**——唯讀；不得執行 build／test／套件管理／docker；不得呼叫其他 AI CLI
3. **問題敘述**

🚫 不備 diff、不給檢查清單、不預設結論、不限定角度——要的是它的觀點。

**問題敘述的撰寫**：只給回答所需的最小脈絡；🚫 不夾帶其他任務或其他 repo 的背景；公司名、內部系統真名、客戶、內部 URL、人名一律換通用化代號；🚫 不整段轉貼對話，改寫成問題本身。

## 7. 採信

顧問給的可執行證據（重現步驟、實測結果、指令輸出）——**自己跑過才算數**。**🚫 不得依顧問意見刪改任何既有內容**，這類建議列入待裁決清單交使用者。否定性主張須查到明確否定依據才採信。採納後自行再驗一次。

> 自主模式的採信權限低於逐次點名：逐次點名時使用者是每次都在場的第二道閘，自主化後這道閘沒了。

## 8. 記帳

每次呼叫後記一列，結案時併入回報或 PR Body：

`來源（自主｜點名）｜命題｜影響範圍｜目的｜命中判準｜指派範圍｜外送敘述｜顧問｜資訊增益 Y/N｜是否改變決策 Y/N`

**資訊增益＝Y** 的條件：回覆含札記中沒有的新候選、反例、具名風險或可執行檢查。「看過覺得沒問題」記 N。

## 9. 退場

任一成立 → 立即停止自主呼叫、回報使用者，本任務其餘諮詢回到逐次點名：

- 作用域或副作用需求改變
- 外送敘述將含機敏識別，或需指派任務範圍外的路徑
- 需要第二支顧問（自主模式限一支）、第二輪追問或延續 session
- 無法唯一判定命題
- 顧問意見會導致刪除、不可逆變更或對外操作
- **連續 2 次資訊增益記 N**（🚫 不得調低門檻續用）

**逐次點名不構成退場**：自主模式啟動後，使用者仍可隨時直接點名要問哪一支——那是一次性的直接指示，執行完模式照舊，🚫 不得視為退場，也不需重新啟動。這類呼叫：

- 🚫 不佔自主預算——預算限制的是「你自己決定要問」，不是「使用者叫你問」
- 允許追問與 `-r` 延續（§4 的禁令只管自主呼叫）
- 點名的顧問可以不是指定顧問（點名即授權），但 🚫 主 AI 不得因此改換指定顧問——更換由使用者明說才算
- 仍記一列，來源標「點名」

## 10. 提問模版

不分專案階段——階段邊界在實務上不可靠，判不出來就不必判。依諮詢目的選問法：

| 目的 | 問什麼 | 禁忌 |
|---|---|---|
| 探索 | 漏了哪類候選、哪個前提若不成立會翻盤 | 🚫 不要它評價你已拍板的選型 |
| 解阻 | 具名衝突是什麼、有哪些裁決方式、各自代價 | 🚫 不夾帶你偏好的答案 |
| 審核 | 給範圍與完成判準，要它自己讀 | 🚫 不預設結論、不給檢查清單、不限定角度 |

共通禁忌：🚫 不問風格偏好；🚫 不要求它產生你已經收斂完的東西（那是用收斂夾帶發散）。

## 11. 回報

附札記與該次呼叫記錄，分別標示「顧問的意見」與「你自己驗證過的結論」，🚫 不得混寫成單一結論。成效以資訊增益與決策改變衡量，🚫 不看呼叫次數。
