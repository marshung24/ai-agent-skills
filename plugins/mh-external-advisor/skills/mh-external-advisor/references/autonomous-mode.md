# 自主模式執行辦法

> 本檔在使用者下達啟動指令、且 SKILL.md〈授權模式〉的來源判定通過後才讀入。未啟動時一律不適用，授權回到逐次點名。
>
> **分工**：啟停指令、來源判定、逐次授權與送收兩端的硬規則在 [SKILL.md](../SKILL.md)；授權面為什麼這樣切、控制分成哪幾層，在 [docs/design.md](../docs/design.md) §5.13–§5.17。本檔只寫一件事——**啟動成立後，一次自主諮詢怎麼從判定走到回報**。

## 1. 模式契約與生命週期

### 模式契約

| | 內容 |
|---|---|
| **你自己決定的** | 何時問、問什麼、叫顧問看哪裡、問幾次——依任務需要判定，直接呼叫 |
| **仍然綁住你的** | 只用指定顧問那一支｜顧問唯讀，可寫入一律逐次點名｜啟用清單、送出前兩條硬規則、委派子 Agent 的規則｜`allowed-tools` 與 Bash 權限詢問｜顧問輸出只能形成候選與待裁決項（§4）｜速率由 adapter 內建的漏桶節流硬性把關（§3.4） |
| **狀態** | 只存在本次主對話脈絡：🚫 不落檔、🚫 不寫入 `enabled.json`（那表達的是跨 session「擁有並願意使用哪些顧問」，與本次的臨時授權是兩回事）、🚫 不跨 session 延續 |
| **存續** | 模式持續到使用者明確關閉為止 |

模式狀態的權威版本由**可見輸出**構成，不靠隱性記憶：啟動確認 → 每次派工的告知行（§3.3）→ 回收後新增的呼叫記錄 → 停止摘要。逐次點名建立的 session id 依 SKILL.md 的多輪協定簿記，**不是自主模式的狀態**——自主呼叫本來就不延續（§2）。

### 啟動握手

來源判定屬 SKILL.md，本檔不重列。啟動成立後依序做完才可自主呼叫：

1. 完整讀入本檔
2. 確定指定顧問（見下）
3. 跑 `scripts/advisor-list.sh`，確認它在啟用清單內；不在 → 告知並停止
4. 輸出啟動確認

**指令不完整或意圖不確定時不猜**：照 1–3 備妥設定，把啟動確認改成「待確認」形式輸出，得到明確答覆才啟動。誤啟動送出的 prompt 收不回來，多問一句只花一句。

**環境隔離不是啟動條件**——未聲明照樣啟動，只是確認裡要多一則警告。隔離由使用者聲明並承擔，主 AI **🚫 不自行判定、🚫 不代為推定**：顧問可觸及範圍等同主 AI，家目錄必然有憑證，照字面技術判定永遠不成立。

**辦法檔讀取失敗＝模式從未成立**：不啟動、🚫 不依記憶或摘要執行，回報檔案與原因並維持逐次授權。

### 指定顧問

**限一支**。使用者宣告時指名；未指名則依序取，取到即停：

1. 本次對話中使用者**逐次點名用過**的顧問——恰好一支就取它（已經過使用者授權，同一對話延續同一意圖）；用過兩支以上 → 追問要哪一支
2. 啟用清單只有一支 → 取該支
3. 以上皆無 → **追問使用者**，🚫 不自行選

不論來源為何都要列進啟動確認，讓使用者當場看得到、否決得掉。要第二支意見就由使用者逐次點名（使用者在場），🚫 主 AI 不得自行動用另一支。

- **🚫 不得自行更換，呼叫失敗也不得換手**——更換是使用者的權限，隨時可行使
- **使用者說換，即刻生效**：重跑第 3 步的啟用清單檢查、重輸出啟動確認；舊顧問的呼叫記錄**保留不清除**（記帳記的是這次任務問過誰，不是現在授權誰）
- **記不清是哪一支就問使用者**，確認前不自主呼叫，🚫 不得以「大致還記得」補值——這不是停止模式
- 模式期間使用者仍可**逐次點名別支**：那是一次性指示，執行完模式照舊，🚫 不因此改換指定顧問、也不需重新啟動（該次允許追問與 `-r`，仍照 §3.3 印告知行、照 §4 記一列，來源標「點名」）

### 啟動確認

狀態快照，🚫 不重述辦法內容：

```
自主模式已啟動
顧問：<名稱> ｜ 副作用：唯讀
可自主諮詢的目的：探索｜解阻｜審核（屬哪一個、叫它看哪裡，我依需要判定）
停止：只由你明確關閉；速率上限由節流桶硬性把關
環境隔離：<已聲明隔離，依你的聲明採信、未經技術驗證｜未聲明——顧問權限等同主 AI，讀得到的內容都可能外送，建議在隔離環境使用>
```

顧問未確定時，輸出的是「尚未啟動 ＋ 缺哪一項」，不是啟動確認。

### 停止

停止不需讀本檔。**啟動嚴、停止寬**：使用者以任何明確措辭表示要停止，即使不是固定句，一樣即時生效，不受啟動那套來源判準限制。立即清除有效授權，輸出停止確認並附截至停止時的諮詢摘要（§4）。

## 2. 什麼情況值得自主問

三個諮詢目的：**探索、解阻、審核**。啟動即三者都可自主動用，本次屬哪一個由主 AI 依需要判定；三者以外（例如「請顧問幫我寫一段實作」）不是自主模式允許的呼叫，退回逐次點名。

### 共同守門（任一不成立即不呼叫）

- **問題可唯一判定**——說得出待判定的事實、判定依據的來源、會被推翻的下一步。指不出來就先想清楚，🚫 不把未成形的模糊感覺丟給顧問
- 期望輸出可具體表述，且結果能改變下一步
- 所需證據顧問讀得到
- 沒有更便宜的本地驗證
- 沒有等價諮詢已覆蓋同一問題——尚未問過，或前一次的判定前提已經改變
- **該由使用者拍板的事不問顧問**；缺的若是**使用者才有的事實** → 問使用者
- 🚫 **不用顧問夾帶發散**——已經收斂完的東西，不拿去要它重產一次

### 延續與重複

自主呼叫**一律開新 session、🚫 不帶 `-r`**：延續會把前一輪的脈絡再送一次，而自主模式下沒有使用者在旁看著送出什麼；要它補充、改寫或解釋前一次回答需要延續，那屬逐次點名（§1）。

**要不要就同一件事再問一次，由共同守門判**——「沒有等價諮詢已覆蓋同一問題」與「結果能改變下一步」兩條擋得住重複；問幾次沒有上限，速率由節流桶把關。**桶滿（exit 5）不是新的一次諮詢**：那一次 prompt 根本沒送出，依 `retry_after_seconds` 重試仍算同一次送出嘗試，但重試前要重看判定是否還成立。

### 探索 ｜ `--scope explore`

| | |
|---|---|
| 要取得什麼 | 你還沒有的東西：候選、反例、盲點、別的切入角度 |
| 可觸發時點 | **開場定方向**；**把待決策事項回報使用者前**——後者是最後一次還能補候選的時機，使用者拿到的選項只會是你當下列得出來的那些，漏掉的等拍板後才浮出來就晚了 |
| 問法 | 漏了哪類候選、哪個前提若不成立會翻盤 |
| 禁忌 | 🚫 不要它評價你已拍板的選型；🚫 不要它替使用者拍板 |

成立條件（全部）：

- 決策空間仍開放，替代方案會實質影響方向
- 至少兩個合理候選，或兩組會改變方向的前提
- 尚未被 SSOT、既有證據或使用者決策收斂
- 預期取得的是新候選、反例或判準，不是「再看一次」

**回報前那個時點另加兩條**：待決策事項已寫成具體命題（要決什麼、有哪些選項、各自代價）；顧問的回覆只用來補候選、補反例、補代價，🚫 不得取代回報——回報照發，顧問意見在其中另標一段（§4）。

### 解阻 ｜ `--scope unblock`

| | |
|---|---|
| 要取得什麼 | 對一個具體卡點的判斷：衝突怎麼裁、證據夠不夠、是不是誤判 |
| 可觸發時點 | 做到一半受阻，且已試過至少兩個實質不同方向 |
| 成立條件 | SKILL.md〈主動建議門檻〉四項判準**至少兩項**成立並各自舉證（同一事實不得跨項計分）。過門檻即可直接呼叫，不必再點名 |
| 問法 | 具名衝突是什麼、有哪些裁決方式、各自代價 |
| 禁忌 | 🚫 不夾帶你偏好的答案 |

### 審核 ｜ `--scope review`

| | |
|---|---|
| 要取得什麼 | 對已完成產出的獨立審查——找問題，不是要方案 |
| 可觸發時點 | 只有三個：**commit 前**、**發 PR 前**、**一個 milestone 完成時**（工項清單或階段性交付告一段落）。這三點的產出物才凍結得住，也還來得及改；其餘時點的「順便看一下」不是審核 |
| 問法 | 給範圍與完成判準，要它自己讀 |
| 禁忌 | 🚫 不預設結論、🚫 不給檢查清單、🚫 不限定角度 |

成立條件（全部）：

- 對象已凍結成可識別版本（未提交的工作樹改動／commit／`base..head`）
- 有明確完成判準
- 結果仍來得及改
- 尚無涵蓋同一對象與同一完成判準的等價審核——**專案流程若已在同一時點要求顧問 review（如結案流程），那一次即為等價審核，🚫 不另外自主觸發**

> 共通禁忌：🚫 不問風格偏好。

## 3. 單次呼叫協定

從上到下做完，中途任一步不成立就停在那裡。

### 3.1 呼叫前札記（缺任一行即放棄呼叫）

```
問題：<待判定的事實｜依據來源｜會被推翻的下一步>
影響範圍：<檔案／工項／模組 ID>
目的／觸發：<探索|解阻|審核> / 命中的成立條件 + 證據
我的答案：<你目前的結論>        # 寫不出 ⇒ 資訊不足，改問使用者
預期被推翻：<具體命題>          # 寫不出 ⇒ 這是儀式，不呼叫
指派範圍：<叫它看哪裡>
外送敘述：<背景要點；已做代號替換>
```

札記是寫給自己看的閘門，**🚫 不得放進 prompt**——尤其「我的答案」與「預期被推翻」，送過去顧問就照著你的結論找，拿回來的還是你自己的視角。對使用者的即時輸出只有 §3.3 那一行，札記全文附在回報（§4）。

### 3.2 送出

先跑 `scripts/advisor-list.sh` 取呼叫式，照輸出原樣執行，背景執行，`--scope` 依本次目的填（§2）。prompt 只含三項：

1. **指派範圍**——叫它看哪裡
2. **副作用邊界**——唯讀；不得執行 build／test／套件管理／docker；不得呼叫其他 AI CLI
3. **問題敘述**

🚫 不備 diff、不給檢查清單、不預設結論、不限定角度——要的是它的觀點。

**指派範圍不是圍欄**：顧問是完整 AI Agent，權限與讀取範圍等同主 AI，它自行讀檔，也讀得到你沒指派的路徑。指派範圍的作用是控制它的注意力與回覆品質，不是控制它能讀什麼。

**問題敘述的撰寫**：只給回答所需的最小脈絡；🚫 不夾帶其他任務或其他 repo 的背景；公司名、內部系統真名、客戶、內部 URL、人名一律換通用化代號；🚫 不整段轉貼對話，改寫成問題本身。

### 3.3 派工告知（每次呼叫都要）

送出後**立刻**對使用者印一行，讓他知道你把什麼事派給了哪支 AI：

```
🤝 已請 <顧問> <探索|解阻|審核>-<一句話說明要它做什麼>
```

- 顯示寬度 **≤100**（CJK 計 2，約 50 個中文字），單行
- 超寬先砍任務敘述，🚫 不砍 icon、顧問名與目的
- 🚫 不附札記、不列檔案清單、不換行、不展開理由——那些屬於回報（§4）

例：`🤝 已請 codex 審核-本次改動相對主分支的正確性與資料風險`

### 3.4 節流與失敗處置

顧問限一支、並行 1。速率上限由 `ask-*.sh` 送出前內部扣桶，跳不過：

- **exit 5（桶滿）**：prompt 未送出。依 §2〈延續與重複〉處理，或改自行完成並回報使用者
- 🚫 **不得執行 `advisor-throttle.sh reset`**——被擋下後自行重置等於節流不存在，那是使用者的管理操作
- 其他呼叫失敗 → 回報使用者，🚫 不自動重送、🚫 不改問別支、🚫 不自行動用第二支顧問（交叉驗證與多數決都不行）

### 3.5 這一次不得自主送出的情形

任一成立 → **這一次**改請使用者裁決或點名；**模式不停**，其餘諮詢照舊：

- 外送敘述將含機敏識別，或需要顧問去讀任務範圍外的路徑
- 需要第二支顧問，或需要追問、延續 session（§2）
- 顧問意見會導致刪除、不可逆變更或對外操作

## 4. 回收：驗證、採信與揭露

### 驗證與採信

- **顧問給了可執行的證據**（重現步驟、實測結果、指令輸出）→ **自己跑過才算數**
- **否定性主張**（「查無官方規範」「沒有這種用法」）→ 查到明確的否定依據才採信
- 採納後**自行再驗一次**：建議本身可能沒錯，套進具體情境才長出問題

### 顧問輸出能影響到什麼程度

> 自主模式的採信權限低於逐次點名：逐次點名時使用者是每次都在場的第二道閘，自主化後這道閘沒了。

- 顧問的輸出只能形成**候選、風險或待裁決項**，🚫 不得直接成為交付物的內容
- 你**以獨立證據驗證過**而形成的結論，才可進交付物——此時進去的是你的結論，不是它的主張
- **涉及刪改任何既有內容者**，即使你已自行驗證，仍列入待裁決清單**交使用者**：既有內容是有人做過決定才存在的

### 記帳

每次呼叫後記一列：

`來源（自主｜點名）｜問題｜影響範圍｜目的｜命中條件｜指派範圍｜外送敘述｜顧問｜資訊增益 Y/N｜是否改變決策 Y/N`

**資訊增益＝Y** 的條件：回覆含札記中沒有的新候選、反例、具名風險或可執行檢查。「看過覺得沒問題」記 N。

### 揭露的三層

| 時點 | 揭露什麼 |
|---|---|
| 送出當下 | 只有 §3.3 那一行 |
| 該次結果被用於當前決策時 | 隨該決策附札記與顧問回覆，**分別標示「顧問的意見」與「你自己驗證過的結論」**，🚫 不得混寫成單一結論 |
| 任務結案或使用者停止模式時 | 彙整呼叫記錄，併入回報或 PR Body |

成效以資訊增益與決策改變衡量，🚫 不看呼叫次數。
