# 自主諮詢辦法

> 自主諮詢預設開啟；本檔在主 AI **第一次要自主呼叫前**讀入。使用者已明確表示不要用外部顧問時不適用（見 SKILL.md〈諮詢模式〉）。
>
> **分工**：入口與停止、送收兩端的硬規則在 [SKILL.md](../SKILL.md)；控制為什麼這樣切，在 [docs/design.md](../docs/design.md) §5.13–§5.17。本檔只寫一件事——**一次自主諮詢怎麼從判斷走到回報**。

## 1. 契約

| | 內容 |
|---|---|
| **你自己決定的** | 何時問、問哪支、問什麼、叫顧問看哪裡、問幾次——依任務需要判定，直接呼叫 |
| **仍然綁住你的** | 啟用清單｜顧問唯讀，要它寫入須使用者點名｜送出前三條硬規則、子 Agent 規則｜`allowed-tools` 與 Bash 權限詢問｜速率由 adapter 內建的漏桶節流硬性把關（§3.4） |
| **停止** | 使用者以任何措辭明確表示不要用即停，點名照常；說恢復才恢復 |

自主呼叫的可見紀錄由**可見輸出**構成，不靠隱性記憶：每次呼叫的告知行（§3.3）→ 回收後新增的記帳列（§4）。

## 2. 什麼情況值得問

### 何時可以問

**想要外部意見就可以問**——第二意見、其他觀點、交叉驗證、盲點檢查、卡點判斷、各自做後對帳都算，不要求先證明高風險、已受阻或試過幾個方向。

只有以下情形不問：

- **已問過等價問題**：相同前提、對象與判準下已有顧問結果；前提、對象或判準已實質改變者可重問，符合〈多支顧問〉理由而改問另一支做獨立驗證者也不算等價。既有流程已在同一時點要求顧問 review（如結案流程）者即為等價
- **缺的是使用者才有的事實或決定**：問使用者
- **要它代寫實作，或代使用者拍板**：可補候選與共識方案，拍板仍是使用者的

### 情境分流（決定 `--scope` 與 prompt 給什麼）

| 目的 | 要取得什麼 | prompt 要給的範圍與判準 | 典型時機（例示，非門檻） |
|---|---|---|---|
| 探索 `explore` | 候選、反例、盲點、替代解讀、不同切入角度 | 探索範圍、已知前提、結果將影響什麼 | 選不可輕易回復的方向；候選間無支配解；未知前提即將固化成契約；即將把待決策事項交使用者；前提失效需重開 |
| 解阻 `unblock` | 對歧義、衝突、證據不足或卡點的判斷 | 待判命題與判定依據來源 | 做到一半拿不定、或已受阻 |
| 審核 `review` | 對可識別產出、改動或已成形結論的獨立審查與交叉驗證 | 審核對象與完成判準；無正式判準時給既有要求或待驗命題 | 不限 |

**待決策事項即將交使用者時**：顧問只用來補候選、反例、代價，🚫 不取代回報；涉及原始需求、核心需求或契約的變動者，先與顧問收斂出共識方案（依 SKILL.md〈有分歧時的討論輪次〉）再交使用者拍板。

### 各自做後對帳

你與顧問就**同一題、同一判準**各自獨立產出（方案、分析、判定），再由你逐項對帳。適用：結論難以單方驗證、需要交叉驗證、方案空間大而怕彼此錨定。

- 獨立性：prompt 🚫 不含你的草稿或傾向；先送顧問（背景）再自己做，或自己做完才讀回覆
- `--scope`：產出方案或分析者 `explore`；對既有對象下判定者 `review`
- 對帳差異依 SKILL.md〈有分歧時的討論輪次〉收斂；回報對帳後的定案與未收斂點，依〈回報給使用者〉

### 多支顧問

可在同一任務動用啟用清單內多支（並行或依序），**與你自己同一支的 CLI 不算候選**（見 SKILL.md〈自主諮詢〉）。🚫 不預設對全清單 fan-out——每多一支，須另成立以下之一：

- 需要獨立交叉驗證（例：兩支各自做後對帳）
- 需要另一支的能力或觀點
- 前一支的結果留有未解的分歧或證據缺口

使用者點名的那支優先。呼叫失敗改問別支，視為新的一次諮詢，照本節重判。

### 延續與重複

延續與開新依 SKILL.md〈延續 vs 開新的判斷〉；交叉驗證、第二意見、對帳一律開新，求乾淨視角。要不要就同一件事再問一次，看是否已問過等價問題；**prompt 未送出的失敗不是新的一次諮詢**（見 §3.4），重送前重看判斷是否還成立。

## 3. 單次呼叫協定

### 3.1 你的結論與預期不進 prompt

你目前的結論、預期問題或假說 **🚫 不放進 prompt**——送過去顧問就照著它找，拿回來的還是你自己的視角。凍結對象與完成判準依 §3.2 照送；審核對象就是結論、或解阻要判的就是某個假說時，該結論或假說作為待驗命題照送，但 🚫 不附你傾向的答案。

### 3.2 送出

先跑 `scripts/advisor-list.sh` 取呼叫式，照輸出原樣執行，背景執行，`--scope` 依 §2 填。prompt 只含三項：

1. **指派範圍**——叫它看哪裡，附回答所需的最小背景
2. **副作用邊界**——唯讀；不得執行 build／test／套件管理／docker；不得呼叫其他 AI CLI
3. **問題敘述**——本次的決策範圍與所依判準寫在這裡（形態依 `--scope`，見 SKILL.md 送出前三條硬規則）

🚫 不備 diff、不給檢查清單、不預設結論、不限定角度——要的是它的觀點。

**指派範圍不是圍欄**：顧問自行讀檔，也讀得到你沒指派的路徑；指派範圍控制的是它的注意力與回覆品質。🚫 不整段轉貼對話，改寫成問題本身。

**審核的寫法**：

```text
這是已凍結的 <產出版本或結論>。
完成判準為 <判準及來源>。
請在指定範圍內獨立審核。
```

🚫 判準不得寫成帶答案的檢查清單（例：「請確認沒有 null、競態與效能問題」）——那是預設結論；只給契約、結果或不可違反條件。

### 3.3 呼叫告知（每次呼叫都要）

啟動 `ask-*.sh` 後**立刻**對使用者印一行。**用嘗試態**：結束碼還沒回來，這一次可能根本沒送出（§3.4）。

```
🤝 正嘗試請 <顧問> <探索|解阻|審核>-<一句話說明要它做什麼>
```

- 單行，顯示寬度 **≤100**（CJK 計 2）；超寬砍說明，🚫 不砍 icon、顧問名與目的
- 本次對話第一次自主呼叫，下一行加註：`（外部顧問自主諮詢預設開啟；不要用請直說）`
- 🚫 不列檔案清單、不展開理由

例：`🤝 正嘗試請 codex 審核-本次改動相對主分支的正確性與資料風險`

### 3.4 節流與失敗處置

速率上限由 `ask-*.sh` 送出前內部扣桶，跳不過；桶依顧問分開計。

**失敗先依結束碼判 prompt 送出了沒有**——未送出才有重送的餘地，且一律不計為一次諮詢：

| 結束碼 | 情形 | 這一次怎麼辦 |
|---|---|---|
| 5 | 桶滿 | 依輸出的 `retry_after_seconds` 退避後可重送，或改自行完成並回報使用者 |
| 6 | 節流檢查失敗（鎖逾時／桶狀態） | 確認成因已排除才可重送；🚫 不得原樣重試——鎖競爭 `ask-*.sh` 內部已退讓過，再跑一次只是重開同一段等待 |
| 2 | 參數錯誤 | 修正呼叫式後可重送；🚫 不得原樣重跑 |
| 127 | 缺依賴或能力檢查失敗 | 有具體證據顯示依賴／能力已恢復才可重送；🚫 不得原樣重試 |
| 其餘 | prompt 可能已送出 | 回報使用者，🚫 不自動重送。**中止背景任務不算未送出**——本地 wrapper 停了，顧問端可能已經在跑 |

`exit 3`（resume 失敗）不列表：只有續輪帶 `-r` 才出得了這個碼，一律依 detail.md 的結束碼契約與〈resume 失敗行為〉處置，接不回來即依〈有分歧時的討論輪次〉停止該討論。

回報未送出的失敗時須明說「prompt 未送出」，以結清 §3.3 那一行。排除成因若要安裝套件、改設定或登入，改請使用者處理。

上表的未送出情形都不扣桶，**但「未送出」不等於「沒扣桶」**——扣桶成功後、顧問 CLI 啟動前被中止，桶就扣了，歸「其餘」列。任何情況都 🚫 **不得執行 `advisor-throttle.sh reset`** 補回額度——那是使用者的管理操作。

## 4. 回收：驗證、記帳與揭露

### 驗證與採信

依 SKILL.md〈顧問回覆的採信原則〉。顧問的主張要經你以獨立證據驗證，才以**你的結論**進交付物；未驗證者只能當候選或標示為未驗證。

### 記帳

**prompt 已送出**的呼叫，每次記一列（未送出的失敗照 §3.4 即時回報，不進帳）：

`來源（自主｜點名）｜顧問｜目的｜問題｜資訊增益 Y/N｜是否改變決策 Y/N`

**資訊增益＝Y**：回覆含你原本沒有的新候選、反例、具名風險或可執行檢查。「看過覺得沒問題」記 N。

### 揭露

| 時點 | 揭露什麼 |
|---|---|
| 呼叫當下 | 只有 §3.3 那一行；該次若未送出，另依 §3.4 明說 |
| 結果用於當前決策時 | 依 SKILL.md〈回報給使用者〉；須交使用者裁決者**分別標示「顧問的意見」與「你自己驗證過的結論」** |
| 任務結案或使用者表示停止時 | 彙整記帳，併入回報或 PR Body |

成效以資訊增益與決策改變衡量，🚫 不看呼叫次數。
