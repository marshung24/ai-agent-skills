# External Advisor（外部顧問：Codex / Claude / Opencode / Antigravity）

把另一個 AI CLI 當顧問：非互動送出 prompt、取回回覆，並可延續同一段對話。

**使用時機：當任務需要不同觀點時——第二意見、交叉驗證、盲點檢查、獨立 review——用本 skill 呼叫異質 AI 取得獨立視角**；自身即可完成且不需外部觀點的任務，不必使用。僅限使用者指定可用的 CLI（見下方授權前提）。

## 觸發守門

### 授權前提（最優先）
使用者買了哪些 AI 不一定。**只可使用「使用者指定可用」的 CLI**——本次對話中使用者點名過（「問 codex」即是指定 codex 可用）或明示可用清單。未經指定不得主動呼叫任何一支；但**可以詢問或建議**（例：「要不要我請 Codex 給第二意見？」），經同意即視為指定。

### 主動建議門檻
使用者未指定任何 CLI 時，僅當任務**至少滿足下列兩項**才可主動建議諮詢外部顧問，且經使用者同意後方可執行（同意即視為指定）：

- **高重要度**：影響重要決策、交付品質或後續大量工作
- **高複雜度**：跨多模組／多系統／多約束，或需獨立推理驗證
- **高影響性**：出錯將造成安全、資料、成本或營運上的明顯損失

未達門檻：不主動提外部顧問，自行完成或向使用者澄清。

### 最小成立條件
「要諮詢另一個 AI CLI（Codex／Claude／Opencode／Antigravity）」的意圖 + 要問的內容 + 該 CLI 經使用者指定可用。缺一不啟動。

### 啟動條件
- 直接啟動：明確要求「問 codex／請 opencode 看／叫 claude 分析／用 agy 跑…」+ 有具體要問或要處理的內容
- 補問後啟動：有「問外部 AI」意圖但沒說要問什麼、或未指定要問哪一支 → 補問，不自動假設

### 不啟動
- 詢問「codex 是什麼」「怎麼裝 opencode」等說明性／設定性問題
- 一般對話、除錯、設計討論，沒有「轉交另一個 AI」的意圖
- 要求「延用 session」但指的是呼叫端 AI 自身的 session（那是各 agent 自身指令檔的範疇，非本 skill）

## 使用方式

**環境安全前提**：腳本以免互動核可旗標執行——被諮詢的 AI 取得執行使用者的完整權限（不限當前目錄），prompt 內容也會送往該 AI 的服務端。僅限已隔離的 sandbox／受控環境使用；環境安全性不明時，先向使用者確認再執行。完整聲明見 README。

腳本位於本 skill 的 `scripts/`，prompt 可用參數或 stdin 傳入：

- 問 Codex：`scripts/ask-codex.sh "問題"`
- 問 Claude：`scripts/ask-claude.sh "問題"`
- 問 Opencode：`scripts/ask-opencode.sh "問題"`
- 問 Antigravity：`scripts/ask-agy.sh "問題"`

回覆印在 stdout；成功且取得 id 時**最後一行為 `[External Advisor <AI名> session_id: <id>]`**（自帶顧問名，多顧問並用時不會記錯歸屬），供延續使用。無法取得 id 時（罕見，主要是 agy 偵測失敗）該行缺席、stderr 印 `[warn]`——該段視同不可延續。`-r` 延續失敗時 exit 3 且**不自動重送**（防重複副作用；agy 僅前置 id 檢查會 exit 3，執行期失敗為 exit 1，詳見 detail.md）。prompt 以 `-` 開頭時，前面加 `--`（如 `ask-codex.sh -- "-r 是什麼"`）。先看 stderr 分流：暫時性錯誤（網路／CLI 問題）→ 同 id 重試；確認 id 失效且無重複執行疑慮 → 才不帶 `-r` 開新重問。

### 延續同一段對話（多輪諮詢）

採「明確 id」而非 `--last`／`--continue`，避免誤接到無關的最近一段：

1. 首次呼叫後，從輸出末行記下 `<id>`
2. 後續追問帶 `-r <id>`：`scripts/ask-codex.sh -r <id> "追問"`
3. **每輪都以最新輸出末行的 id 更新簿記**——部分 CLI 版本 resume 會 fork 出新 id，沿用舊 id 會靜默遺失中間輪次
4. 你（呼叫端）把 `<id>` 保存在**本次對話脈絡**即可，不需檔案或環境變數
   - `/clear` 後脈絡清空、id 自然遺失 → 下次即開新對話，無需額外清理

### 延續 vs 開新的判斷（呼叫端自行決定）

判準：**這次要問的內容，是否依賴顧問在該段對話中已知的前文？**

- **延續（帶 `-r`）**：追問／深入同一議題、要求補充或修正它先前的回答、系列任務共用同一脈絡（前文已給過的程式碼／背景不必重貼）
- **開新（不帶 `-r`）**：獨立的新問題；或**刻意要乾淨視角**——請顧問獨立驗證、第二意見、adversarial review 時，帶前文反而造成錨定偏誤，應開新
- 不確定時：內容自包含（prompt 內附齊所需背景）→ 開新；要省重貼的長前文 → 延續
- 多段並存時：在對話脈絡記錄各段「CLI／主題／id」對照；「繼續問剛剛那個」無法唯一對應到某段時先補問。腳本只能偵測無效 id，**有效但屬別段的 id 偵測不到**（會靜默接錯脈絡）——歸屬不確定一律開新並附齊背景

### 子 Agent 與本 skill（原則禁用）

**子 Agent 不得使用本 skill**。唯一例外：主 Agent 明確委派的**單次自包含諮詢**——不帶 `-r`、不回報 id、該段對話用後即棄。**id 不跨 agent 邊界傳遞**：跨界延續會產生 owner 沒看過的前文，之後任何一方再延續都是盲區，不可靠。

- 多輪（需延續）的諮詢與 id 簿記一律由主 Agent 親自負責；背景／並行呼叫必先遵守 [references/detail.md](references/detail.md) 的規則（重點：每個呼叫的輸出獨立回收；agy 開新勿並行）
